Question: Is this preset well-designed? What is it missing, where will it mislead someone configuring a real review?

Seats: Contrarian (skin — the engineer who configures a real review from it cold), First-Principles, Expansionist, Outsider (bare artifact), Executor. Plus 3 gap-pass reviewers + adjudication. The reframe that organizes everything

All three gap-pass reviewers independently converged: the advisors judged the preset as if it were the skill. A preset owes its reader one worked example of seat-skinning. The apparatus they faulted it for missing — how context is withheld from the Outsider, the canonical seat roster, the report-don't-prescribe rule, the clean spawn — all live in SKILL.md, which the advisors could not see. This down-weights several harsh findings and sharpens the few that are genuinely the preset's own.

Adjudication

Flag upThe self-hostable default bias. The audience descriptor ships with "we value explicit, operable, self-hostable infrastructure over managed-service convenience" baked in as a default. The clearest answer to "where will it mislead." The descriptor is meant to hold a team's real values — but as a shipped example default, it teaches the copy-paste user to smuggle a conclusion into the supposedly-neutral scope line, pre-biasing every review against the managed answer before the Contrarian speaks. Comfortable to wave away as "just sample text" — which is exactly why it's flagged, not bracketed. An example's defaults are its most-copied part.
MeritMissing pieces — engage.
  • "The relevant code / configs / manifests" has no bounding heuristic. For a real system this is dump-everything vs. guess — both poison the review. Add blast-radius / the-diff / files-touched guidance. (Executor)
  • [reversible / one-way-door] is an un-owned bracket — flagged as strongly affecting scope but never says who picks it or when. Make it a required framing input. (Executor, Expansionist)
  • Point to where Outsider-isolation is enforced (the SKILL.md context-isolation matrix), so a standalone reader doesn't think they must hand-build it. (residue of Contrarian/Executor)
Clash — not resolvedKill the Executor vs. overlap is the product. First-Principles: the Executor catches nothing its neighbors don't ("no path to production" is already First-Principles' wrong-problem + Contrarian's won't-survive-3am); "migration path" is a checklist, not a stance; bold KEEP is the tell. Expansionist: the Watch-item's whole point is that overlap is signal — two seats reinforcing is the strongest reason to stop. They can't both be right about what overlap means. Input for you: SKILL.md already makes the Executor optional and notes dropping it unpairs First-Principles — so the skill's own heuristic is First-Principles' argument; the bold KEEP is the disputed domain recommendation.
MistakenSet aside, with reason.
  • "Operational lie / breaks execution" framing of the Outsider mechanic — SKILL.md owns the mechanic (context-isolation matrix + explicit "spawn it clean"). Only the doc-pointer residue (above) survives.
  • "Undefined terms / Outsider paradox" — terms are defined in SKILL.md/README; the paradox conflates the operator (needs the apparatus) with the Outsider sub-agent (gets the bare artifact). Residue: expand ADRs on first use, since the preset can be dropped into a framing step detached from the repo.
Out of scopeBracket to the parent skill.
  • "Watch-item contradicts report-don't-prescribe" — naming "a simpler shape would have avoided this" is reporting a flaw, not rewriting the design; the sibling preset's Contrarian does the same and the guardrail holds. Watch the phrasing; not a live defect.
  • "Executor is a checklist — move it to the output template" — a SKILL-level redesign, not something this preset can decide. Executor-optionality already lives there.
StrengthenStrengthening track (Expansionist) — act on, don't defend.
  • Worth it: surface the reinforce-vs-diverge primitive instead of burying it as the last footnote — it's a reusable adjudication idea (convergent agreement vs. stacked independent failure modes), the strongest thing in the file.
  • Worth it: make the reversible / one-way-door dial load-bearing and say why — irreversibility is exactly when developmental beats convergent review. The best argument for using the tool at all.
  • Skip as scope-creep: promoting these into the council core — that's a SKILL.md decision; cross-referencing is enough for the preset.

Bottom line

Well-designed? For its job — a worked seat-skinning example — largely yes. The skins are vivid and the engineering Watch-item is genuinely good. Most of the harshest critiques aimed at the parent skill, not this file.

Missing? A code-bounding heuristic, a required reversibility input, a pointer to Outsider enforcement, and the reinforce-vs-diverge idea pulled up where it can be seen.

Where will it mislead? (1) The self-hostable-over-managed default silently biases every review built from it. (2) The "but NOT for the Outsider" line, read standalone, looks like an instruction the configurer must hand-implement when the skill already handles it.

Full advisor responses

Contrarian — the engineer configuring a real review from this preset

The preset's biggest operational lie is the Outsider boundary, and a real user will get it wrong. Step 1A says "gather domain context... but NOT for the Outsider" — but this is a reference doc dropped into a framing step, not enforced code. Nothing tells the configuring engineer HOW to withhold context from one seat while feeding four others. The user reads it, nods, and pastes the whole bundle into a shared frame anyway. The seat that's supposed to catch the onboarding cliff now silently holds the system in its head — quietly, with no error.

Second, the Watch-item contradicts "report, don't prescribe" and the artifact never reconciles it. The Contrarian skin is told to argue "the simpler shape that would have avoided this" and First-Principles "don't build this." Two seats are now both prescribing a verdict.

Third, "self-hostable infrastructure over managed-service convenience" is baked into the audience descriptor as a default. A thumb on the scale — any review run from this preset is pre-biased against the managed-service answer before the Contrarian opens its mouth.

First-Principles

The Executor seat is dead weight, and the preset's own logic exposes it. The real test of every seat: what does it catch that no other seat catches? The Executor's flagship catch — elegant on paper, no realistic path to production — is already caught twice: First-Principles says the elegance solves the wrong problem, Contrarian says it won't survive 3am. "Migration path" and "ship incrementally" aren't a thinking stance; they're a checklist — and a checklist needs a line in the output template, not a seat.

The Watch-item is a confession: Contrarian and First-Principles "will often both say don't build this." The author flagged overlap on the wrong pair. The genuine redundancy is Executor ↔ the don't-build-this consensus. You wrote "KEEP for engineering" in bold — that emphasis is the tell. Does operability-and-shipping need a thinking stance, or a rubric?

Expansionist

The strongest thread is the "Watch-item specific to engineering" — buried at the bottom as a footnote. It encodes a rule for distinguishing convergent agreement (two seats happen to land on the same verdict) from compositional signal (two independent failure modes stacking). "Reinforce = strong signal to stop; diverge = two separate problems" is a reusable adjudication primitive, not an engineering quirk. It belongs to the council's core thesis and generalizes to every preset.

The second undervalued asset is the reversible-vs-one-way-door descriptor. You note it "strongly affects what counts as in-scope" and move on. That dial deserves to be load-bearing: irreversibility is precisely when the council's developmental stance pays off most — the strongest argument for why this tool beats a straight answer.

Outsider — bare artifact, zero context

The document is itself a configuration for the council. Used as if known: "developmental council," "seats," "framing step," "adjudication layer," "Step 1A," "tension-pairs," "skin" (never defined). "ADRs" with no expansion (inferring Architecture Decision Records). "one-way-door," "CLAUDE.md," "operability" all assumed. The seats are named as if a canonical roster exists elsewhere; "KEEP for engineering" implies some seats get dropped, but the default set is never stated.

What doesn't add up: the doc tells the Outsider to read with no system knowledge, yet to occupy the seat I must already understand the whole council apparatus. The instructions presuppose the very insider context the seat is supposed to lack. The clearest part: the Watch-item — stands on its own without outside context.

Executor

The Outsider carve-out is where execution breaks. The preset says "but NOT for the Outsider," but the seat config spawns five sub-agents from one framing step, with no mechanic for starving one. Monday morning: a different prompt? A redacted artifact? An AI running the skill will hand all five the same bundle — path of least resistance — and the differentiator silently collapses.

Second: "the relevant code / configs / manifests" has no first step for a large system. Which files? No heuristic (blast radius? the diff?). Someone dumps everything or guesses — both poison the review.

Third: the "[reversible / one-way-door]" fill-in-the-blank is flagged as strongly affecting scope but never says who decides or when. It needs to be a required input, not a bracketed suggestion. The seat list is otherwise immediately actionable.
